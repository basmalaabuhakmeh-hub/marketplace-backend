Full Postman test plan
======================

Restart both apps first.
1. Redis (Docker): docker run --name redis -p 6379:6379 -d redis
   If the container already exists: docker start redis
2. ForgetPassword-microService on port 8081
3. Then this marketplace on port 8080

Base URL: http://localhost:8080
OTP service: http://localhost:8081  (do not verify OTP here first — that burns the code)

Postman habit:
- /auth/**  -> Authorization = No Auth, Body = raw JSON
- everything else -> Authorization = Bearer Token
  Type = Bearer Token. Paste ONLY the eyJ... string (do not type "Bearer ").
- Body email/password on a GET does nothing. Token goes on the Authorization tab of THAT request.
- After every app restart, login again. JWT secret is new; old tokens die.

Use new emails if these already exist (seller2, customer3, driver3, ...).

Keep 5 tokens: ADMIN_TOKEN, SELLER_TOKEN, CUSTOMER_TOKEN, CUSTOMER_B_TOKEN, DRIVER_TOKEN.

productType must be one of: Electronics, ComputerAccessories, MobileAccessories
paymentType must be one of: CASH, CREDIT
  CREDIT -> paymentStatus PAID as soon as the order is placed (card is simulated here).
  CASH   -> paymentStatus PENDING until the driver collects after DELIVERED
            PUT /orders/{id}/pay  (ADMIN or assigned DRIVER only).

Validation 400 body (missing/blank/invalid fields, bad ids, bad paging):
{
  "status": 400,
  "message": "Validation failed",
  "errors": { "email": "Email must be valid" }
}
Business 400s (not enough stock, wrong order status) still use Spring's default error JSON, not this map.
Invalid productType (e.g. "Food") -> 400, errors.body says it must be one of the three types.
GET /products/0 (or any id 0) -> 400, not 404. Use 99999 for 404.
Password min length is 4, so accounts in this file still work.

Redis catalog cache (customer + admin GET /products only):
- Method must be GET (PUT /products is 405).
- Key is pageNo-pageSize, e.g. productCatalog::0-10 (ttl 10 minutes).
- 1st GET /products?pageNo=0&pageSize=10 -> IntelliJ shows product SQL.
- 2nd GET same URL -> 200, same JSON, NO new product SQL (users SQL from JWT is normal).
- Seller GET /products is NOT cached (own products only).
- Create/update/delete product, place/cancel order, or delete seller -> cache is cleared; next customer GET hits SQL again.
Check keys: docker exec -it redis redis-cli
  KEYS *
  GET productCatalog::0-10   (may look like JSON)

MySQL note: users.role must include DRIVER
  (enum ADMIN, CUSTOMER, SELLER, DRIVER). ddl-auto=update will not add it.

Notes
-----
- After restarting the app, login again. JWT secret is new, old tokens stop working.
- Forgot/reset: same email for forgot, console OTP, and reset. Marketplace 404 = email not in users.
- Products created before stock was added may have stock = 0. Update them with PUT first.
- If a new driver is saved as SELLER, the running app is stale — restart IntelliJ — and check users.role includes DRIVER.
- Auth is per Postman request. Setting the token on /auth/login does not send it on GET /drivers.
- After a successful reset, that user's password in this file (1234) is stale until you set it back or keep using new123.
- Validation 400 = { status, message, errors }. Stock/status 400s are a different Spring JSON.
- Order flow is PLACED -> ACCEPTED -> SHIPPED -> assign driver -> DELIVERED (or CANCELLED while PLACED).
- CASH: PENDING on place, PAID via PUT /orders/{id}/pay after DELIVERED. CREDIT: PAID on place.
- Redis must be up on 6379 or GET /products may fail. Catalog cache is customer/admin only.
- Status emails go through 8081 POST /email/send. If 8081 is down, the order still succeeds.
